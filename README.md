# project-init

A project-agnostic working agreement for AI coding agents (Claude Code,
Codex, Cursor and any agent that reads `AGENTS.md`).

Drop two files into a repository and the first session sets the project up
for the type of product you are building: a website, a mobile or desktop app,
a game, a hardware+software system…

## What it enforces

- **Think before building:** understand the product goal, ask only
  non-trivial questions, split large requests into slices, compare approaches.
- **Reuse before writing:** repo → standard library → platform → installed
  dependency → well-established library → minimal new code.
- **Simplicity:** small, readable, easy-to-locate code; abstraction only when
  the design needs it.
- **Never cut:** validation, data-loss handling, security and accessibility.
- **Single source of truth:** theme tokens, config, i18n and contracts in one
  place each.
- **No legacy:** obsolete or unexplained code is removed, no exceptions.
- **Performance awareness:** algorithmic complexity and chatty communication
  are considered up front.
- **Clear reporting:** every finished change is summarised as
  `type(scope): description` commit lines.
- **Memory:** a local, size-limited `MEMORY.md` of past → present → future
  patterns, so each session learns from the previous ones.

## Usage

1. Copy `AGENTS.md` and `CLAUDE.md` to the root of your repository.
2. Open a session with your agent. Since `PROJECT.md` does not exist yet, the
   agent runs the **bootstrap**:
   1. detects the stack (or asks what you are building, if the repo is empty);
   2. proposes the responsibility map, sources of truth and CI pipeline;
   3. generates them after you confirm.

`CLAUDE.md` exists because Claude Code reads `CLAUDE.md`, not `AGENTS.md`; it
only imports the other files.

## Layers

| File | Holds | Shared |
| --- | --- | --- |
| `AGENTS.md` | How to work, for any product | Committed; evolves through promotions |
| `PROJECT.md` | Product, stack, responsibilities, conventions, CI | Committed, generated by bootstrap |
| `MEMORY.md` | Personal patterns: tried → corrected → result | Local, git-ignored |
| `CLAUDE.md` | Imports the three files above for Claude Code | Committed |

Lessons flow upwards: personal preferences stay in `MEMORY.md`, project rules
are promoted to `PROJECT.md`, and rules useful anywhere are promoted to
`AGENTS.md`.

See [`examples/PROJECT.example.md`](examples/PROJECT.example.md) for what a
generated `PROJECT.md` looks like.
